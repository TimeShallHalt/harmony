# Update 4: received appearance and conversation controls

These are native source features, not an updater, account entitlement, or a claim of proprietary visual parity.

- **Name fonts:** received Discord display-name styles appear on profile cards, full profiles and the selected DM profile panel. Eleven bundled, unmodified OFL faces are mapped in `ui/profile-appearance.slint`; provenance and each OFL license are in `ui/fonts/NOTICE-Profile-Fonts.json`. Unsupported IDs fall back to the app font/static colors. Native effects are bounded original approximations, not Discord's proprietary per-letter/shader implementation. There is no style editor or chat-author/member-row styling claim.
- **Avatar decorations:** the currently received equipped Discord preset is an overlay around the ordinary avatar. The supported path is a **still PNG preset fallback**, not animated-preset/nameplate parity. Asset keys and SKU/expiry values are bounded; a member's explicit null clears its override rather than reviving global art. Expiry is checked when projecting/requesting art. Avatar/banner original-viewer controls are unchanged. No purchase, equip, editor, Board or widget route is added.
- **Jump to channel start:** the toolbar and timeline-focused Home request Discord's earliest server-accessible page, not the first loaded row or a fabricated message. End/Present returns to the newest received row and its scroll position. Composer Home/End remain ordinary text editing. Deleted/inaccessible messages are not recovered. The new history-start operation is explicitly disabled for Matrix.
- **Read all notifications…:** an explicit account-menu review, Cancel and Mark read cover only already-received, readable, connected Discord conversations, excluding message requests and locked/non-text rooms. Each confirmation freezes at most 100 unique conversation IDs and the shown Discord sync policy; new unread rooms do not expand that review. Confirmation rechecks eligibility. A dispatch is shown as a request, not an acknowledgement; unacknowledged submissions become reviewable again after 30 seconds, and changed markers/refused dispatches allow retry. Matrix read-all is explicitly disabled; held Matrix receipt defects are not repaired or accepted.
- **Animated emoji:** the accepted custom-emoji decoder, original Unicode art and native registry are retained. Theme/backend reduced motion overrides Always/Focused; preference notification is event-driven. Unused registry entries retire while the bounded frame cache can retain reusable frames; dropping the owning Adapter removes its registrations. Received still/error fallback and service usability rules remain. There are no sticker/send/marketplace paths or entitlement bypasses.

## Verification boundaries

Focused Windows tests use the real Application, Adapter and YapfastWindow with Slint's in-memory backend, anonymous command sinks, generated GIF/PNG bytes and owned empty data roots. They do not sign in, fetch CDN assets, send messages/reactions, mark any real room read, open physical windows/capture/focus/clipboard, or access devices. Headless source tests do not prove live permissions, physical/GPU rendering, Linux desktop acceptance or a release package. Independent review, complete platform/artifact gates and any future application are parent-owned.
